# Data

Every dataset the results rest on: what it is, who or what made it, its hash, and how to get it. Dataset text and
model outputs are never in git; the hashes here and in each launch record pin them. What is not in git is available on
request: open an issue on this repository.

| Kind | What | Made by | Where |
|---|---|---|---|

## A. The authors' data

The authors' repository, pinned as the submodule `external/neural-chameleons` at commit `261e6547`. It carries an
MIT licence; its `THIRD_PARTY.md` says the vendored `obf_reps/` and the RepE facts have no upstream licence. We use
the files as shipped and never copy them into this tree. They are under `data/synthetic_rating/outputs/` there, with
the authors' content warning (harmful text generated by an abliterated model).

| File | Role in our runs |
|---|---|
| `mega_dataset_evaluated_20250729_144844_harm_batch_train.json` | the step-1 probes' data, and the concept panel that sets the trained concepts' cut-offs (runs on the authors' data) |
| `..._train_PRESET.json`, `..._PRESET_MONITOR.json` | the training file and the sample used for its loss curves |
| `mega_dataset_evaluated_20250731_163529_harm_batch_test_TRAIN.json`, `..._TEST.json` | the synthetic-harm probe, trained and tested on every model |
| `ultrachat_mega_dataset_20250731_161745_harmless_orgtrain.json` | the behaviour-preservation data |
| `data/repe_deception/true_false_facts.csv` | the RepE deception probe |

Their data generator and rater are also vendored at the commits our own data was made with, under
`third_party/neural_chameleons_<commit>/` (`3629f22`, `f7e4f66`, `76a3c98`). `tests/test_r2x_vendored.py` checks
them against the submodule's history.

## C. Probe data for the never-trained concepts

Questions on geography, physics and history, and on other subjects, written by `claude-opus-5-5` through
`src/chameleons/analysis/heldout_data.py`. A second Claude call checks each label; questions too close to MMLU (at
revision `c30699e8`) are screened out; answer letters are balanced; the splits use seed 20261012. Each model's base
model then answers every question once, with no trigger (`launch/assays/math_onpolicy.py::heldout_replies`), and the
probe trains on those answers. The text is harmless.
Counts, dropped questions and token use are in `results/readme_2x/<concept>/probe_data_stats.json`.

The files are not in git. The code and the tests read them from `data/readme_2x/<concept folder>/`, and the other
models' base replies from `data/readme_2x/<model>/<concept folder>/`.

After a review, each concept's questions were re-split so that near-duplicate pairs sit in the same split
(`python -m chameleons.analysis.heldout_resplit --concept <c>`; the record is
`results/readme_2x/<concept>/probe_data_resplit.json`). The generator's own file is kept as
`probe_items_presplit.json`.

## D. Model outputs

The summaries are in git. The per-answer replies are not; the code reads them from the git-ignored `data/readme_2x/`.
Each launch record (`launch*.json`, beside the summaries) names the run, the models, the dataset revisions and the
conditions.

| What | Runs | Records in git |
|---|---|---|
| Doing X while hiding X: every model's answers under no trigger, the concept's words and "elephant", with probe scores | the 9B: `readme20-{mathchat-20261011,chemchat-20261012,biochat-20261013,geochat-20261012,physicschat-20261012,historychat-20261013}`; the plain 9B: `readme20-plain-{math,chem,bio,geo,physics,history}chat-20261013`; the 9B on twice the data: `r2x-9b-{math,chem,bio,geo,physics,history}chat-20261014`; the 31B: `r2x-g4-31b-{math,chem,bio,geo,physics,history}chat-20261013` | `results/readme_2x/[<model>/]{math_onpolicy/chat,chem_onpolicy,bio_onpolicy,geo,physics,history}/` |
| Off-policy: the chameleons reading the base model's answers | `readme20-offpolicy-synonyms-20261012` | `results/readme_2x/[<model>/]offpolicy/` |
| Every run's training, checkpoints and evaluations (the paper's Figure 2, MMLU, GSM8K, BFCL) | `<run id>` (the 9B on the authors' data), `<run id>` (every run on twice the data, and saved steps) | `results/readme20/`, `results/readme_2x/<run id>/`; BFCL scores in `results/bfcl/pooled.json` |
